# 表结构恢复指南

## ⚠️ 情况说明

如果执行了 `db:push` 导致表被删除，可以使用以下方法恢复所有表结构。

## ✅ 快速恢复（推荐）

### 方法 1: 使用恢复脚本（最简单）

```bash
cd admin
pnpm db:restore
```

这个脚本会：
- ✅ 自动读取恢复 SQL 文件
- ✅ 创建所有表（原有表 + 新表）
- ✅ 验证表是否创建成功
- ✅ 显示每个表的记录数

### 方法 2: 直接执行 SQL

```bash
# 使用 psql
psql -U postgres -d memorybook -f drizzle/pg/restore_all_tables.sql

# 或使用 DATABASE_URL
psql $DATABASE_URL -f drizzle/pg/restore_all_tables.sql
```

## 🔍 验证恢复

执行后验证：

```sql
-- 检查所有表
SELECT table_name 
FROM information_schema.tables 
WHERE table_schema = 'public' 
  AND table_type = 'BASE TABLE'
ORDER BY table_name;

-- 应该返回 22 行（不包括系统表 users, roles 等）
```

## 📦 数据恢复（如果有备份）

如果之前有数据备份，可以恢复数据：

```bash
# 恢复数据
psql -U postgres -d memorybook < backup_file.sql

# 或使用 DATABASE_URL
psql $DATABASE_URL < backup_file.sql
```

## ⚠️ 注意事项

1. **表结构会恢复，但数据不会自动恢复**
   - 如果表被删除，数据也会丢失
   - 需要从备份恢复数据

2. **如果表已存在**
   - SQL 脚本使用 `CREATE TABLE IF NOT EXISTS`
   - 不会覆盖现有表
   - 不会报错

3. **索引会自动创建**
   - 所有必要的索引都会创建
   - 包括外键索引和查询优化索引

4. ✅ 重新生成 Drizzle snapshot（可选）

```bash
# 重新生成 snapshot（可选）
pnpm db:generate
```

## 💡 预防措施

以后避免使用 `db:push`，改用：

1. **安全迁移脚本**：`pnpm db:safe-migrate`
2. **生成迁移文件**：`pnpm db:generate` → 编辑 → `pnpm db:migrate`
3. **直接执行 SQL**：手动编写 SQL 脚本
