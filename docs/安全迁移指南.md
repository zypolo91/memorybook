# 安全迁移指南

## ⚠️ 重要提示

**不要直接执行 `db:push`！** 它会删除所有现有表和数据。

## 问题原因

Drizzle 检测到 schema 变化，想要重新创建所有表。这是因为：
1. Schema 配置已修复（现在会读取 `schema.memorybook.ts`）
2. 但 Drizzle 认为需要重建所有表来匹配新的 schema

## ✅ 推荐方案：使用安全迁移脚本（最简单）

### 方案 1: 使用安全迁移脚本（⭐ 强烈推荐）

```bash
pnpm db:safe-migrate
```

这个脚本会：
- ✅ 自动检查表是否已存在
- ✅ 只创建不存在的表
- ✅ 不会删除任何现有表和数据
- ✅ 显示详细的执行日志

### 方案 2: 直接执行 SQL 脚本

```bash
# 连接到 PostgreSQL
psql -U postgres -d memorybook

# 执行迁移脚本
\i drizzle/pg/add_new_tables.sql
```

或者使用环境变量：
```bash
psql $DATABASE_URL -f drizzle/pg/add_new_tables.sql
```

### 方案 3: 使用 Drizzle Migrate（需要手动编辑）

```bash
# 1. 生成迁移文件
pnpm db:generate

# 2. 检查生成的迁移文件（在 drizzle/pg/ 目录下）
# 3. ⚠️ 重要：手动编辑迁移文件，删除所有 DROP TABLE 语句

# 4. 执行迁移
pnpm db:migrate
```

## 🔍 验证迁移

执行 SQL 查询验证表是否创建成功：

```sql
-- 检查新表是否存在
SELECT table_name 
FROM information_schema.tables 
WHERE table_schema = 'public' 
  AND table_name IN (
    'medical_categories',
    'medical_records',
    'medical_tags',
    'medical_record_tags',
    'location_records',
    'geofences',
    'geofence_alerts'
  )
ORDER BY table_name;
```

应该返回 7 行。

## ⚠️ 如果必须使用 db:push

**只有在开发环境且可以接受数据丢失的情况下才使用：**

```bash
# 1. 先备份数据
pg_dump -U postgres memorybook > backup_$(date +%Y%m%d_%H%M%S).sql

# 2. 执行 push（会删除所有表）
pnpm db:push

# 3. 如果需要，恢复数据
psql -U postgres memorybook < backup_*.sql
```
